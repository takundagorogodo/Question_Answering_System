Retrieval-Augmented Generation

Retrieval-Augmented Generation, commonly abbreviated as RAG, is an architecture that combines a retrieval system with a generative language model in order to produce answers that are grounded in real source documents, rather than relying purely on what the language model happens to have memorized during its training.

A generative language model on its own has two significant weaknesses when used for question answering. First, its knowledge is limited to whatever was present in its training data, which means it will know nothing about documents, facts, or domains that were not part of that training data, such as a specific company's internal documents or a student project's custom knowledge base. Second, when asked something it does not actually know, a language model will often still generate a fluent, confident-sounding answer that is factually wrong, rather than admitting uncertainty. This behavior is called hallucination.

RAG addresses both problems by inserting a retrieval step before generation. When a user asks a question, the system first searches a collection of documents to find the passages most relevant to that question. This search is typically performed using semantic similarity between vector embeddings, rather than simple keyword matching, so that it can find relevant passages even when they are worded very differently from the question itself. The retrieved passages are then inserted into the prompt given to the generative model, alongside the original question, with an instruction to answer using only the provided information.

This approach has several practical benefits. It allows a generative model to answer questions about custom, private, or newly created content without needing to retrain the model itself, since new knowledge can simply be added to the document collection. It also makes answers more auditable, because the system can show which passages were retrieved and used to generate a given answer, letting a user judge for themselves whether the answer is well supported. Finally, because the model is explicitly instructed to rely on the retrieved context, RAG tends to substantially reduce, though not entirely eliminate, the rate of hallucinated answers compared to a generative model working from memory alone.

RAG is not a single fixed algorithm but rather a general architectural pattern, and real systems vary in how they perform retrieval, how many passages they retrieve, whether they rerank retrieved passages before generation, and how the retrieved context is formatted in the prompt. A generative question answering project built around RAG needs to make deliberate, explainable choices at each of these steps.
