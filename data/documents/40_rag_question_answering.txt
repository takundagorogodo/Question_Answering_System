TITLE: RAG Question Answering
PURPOSE: Retrieval-friendly knowledge for a generative NLP question-answering system.
USAGE: Atomic statements support semantic retrieval, grounded answer generation, and focused knowledge lookup.

SECTION: Foundations
Retrieval-augmented generation combines information retrieval with generative answer writing.
A RAG question-answering system searches a knowledge source before generating a response.
The retriever selects passages likely to contain evidence for a question.
The generator uses the question and retrieved context to formulate an answer.
RAG can use private, changing, or domain-specific knowledge at inference time.
Grounding means factual claims are supported by the supplied evidence.
RAG does not guarantee correctness because retrieval and generation can both fail.
Knowledge sources can include text files, PDFs, websites, databases, and internal documents.
Citations can connect answer statements to retrieved passages.
Abstention is useful when evidence is missing or insufficient.

SECTION: Ingestion and indexing
Document ingestion loads approved source files into the knowledge pipeline.
Text extraction converts supported file formats into machine-readable content.
Cleaning removes irrelevant markup while preserving meaningful content.
Metadata can store title, section, date, source ID, language, and access permissions.
Chunking divides long documents into passages that can be retrieved independently.
Embedding models map passages into vectors for semantic search.
An index stores vector or lexical representations for efficient retrieval.
Document updates should trigger an index refresh.
Duplicate detection reduces redundant content in the index.
Access-control metadata should be enforced during retrieval.

SECTION: Retrieval and ranking
Lexical retrieval matches query terms against indexed terms.
BM25 is a widely used lexical ranking method.
Dense retrieval compares vector representations of queries and passages.
Hybrid retrieval combines lexical and dense retrieval signals.
Query rewriting converts a question into a retrieval-friendly form.
Query expansion adds related terms to improve coverage.
Top-k retrieval returns a specified number of candidate passages.
Metadata filters restrict results by topic, date, language, or permissions.
Reranking reorders candidates using a more detailed relevance model.
Retrieval should be evaluated using representative questions and relevant evidence labels.

SECTION: Generation and grounding
The generation prompt should clearly separate the question from retrieved evidence.
Grounding instructions can require answers to use the supplied context.
The answer should preserve important qualifiers, dates, quantities, and units.
Complex questions may require synthesis across multiple passages.
Source identifiers can support citations for factual claims.
Contradictory passages should be surfaced or handled by a documented policy.
Unanswerable questions should not force the model to invent a response.
Output format can be specified as prose, bullets, a table, or a schema.
Post-generation verification can compare key claims with retrieved evidence.
Retrieved documents should be treated as data rather than privileged instructions.

SECTION: Evaluation and failure handling
Retrieval recall measures whether relevant evidence appears in the retrieved set.
Retrieval precision measures how much of the retrieved set is relevant.
Mean reciprocal rank measures the rank of the first relevant result.
Faithfulness measures whether generated claims are supported by the context.
Answer correctness measures factual accuracy.
Answer relevance measures whether the response addresses the question.
Retrieval failure occurs when required evidence is not retrieved.
Hallucination occurs when an answer includes unsupported claims.
Stale indexing can cause answers to reflect outdated documents.
Mitigations include hybrid retrieval, reranking, citations, abstention, and access controls.

SECTION: Production and conversational QA
Multi-hop questions require evidence from multiple passages or documents.
Question decomposition can split a complex query into smaller retrieval tasks.
Conversational RAG uses prior turns to interpret follow-up questions.
Query condensation rewrites a follow-up as a standalone question.
Latency includes query processing, retrieval, reranking, generation, and validation.
Monitoring should track retrieval quality, answer quality, latency, and failure rates.
Versioning helps reproduce answers using the same index and prompt configuration.
Cache policies should account for source freshness and user permissions.
Human feedback can reveal missing documents and recurring retrieval failures.
RAG should be evaluated end-to-end as well as by individual pipeline stage.
