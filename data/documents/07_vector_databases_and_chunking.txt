44. RETRIEVAL FAILURE
A system may fail because:
- The answer is absent.
- The wrong chunk is retrieved.
- The relevant chunk is ranked too low.
- Chunking separated required context.
- Embeddings do not capture the required relationship.

45. CHUNKING AND CONTEXT WINDOW
Retrieved chunks must fit within the language model's context limits.
Chunk selection should balance:
- Relevance
- Coverage
- Context size

46. PRACTICAL CHUNKING STRATEGY
A general approach:
1. Preserve document structure.
2. Split by meaningful sections where possible.
3. Keep related sentences together.
4. Use moderate overlap when needed.
5. Store rich metadata.
6. Test retrieval quality.
7. Adjust chunk size based on results.

47. EVALUATING CHUNKING
Evaluate whether:
- Relevant answers are contained in individual chunks.
- Retrieved chunks provide enough context.
- Unrelated text is minimized.
- Sources remain traceable.
- Multi-chunk questions can be answered.

48. COMPLETE VECTOR QA ARCHITECTURE
Documents
→ Parsing
→ Cleaning
→ Chunking
→ Embedding
→ Vector Database

Question
→ Embedding
→ Similarity Search
→ Optional Metadata Filter
→ Optional Reranking
→ Relevant Chunks
→ Transformer
→ Answer
→ Sources

49. KEY PRINCIPLE
Good vector retrieval depends not only on the vector database.
Document quality, chunking, embeddings, metadata, search configuration, and retrieval strategy all affect results.

50. FINAL SUMMARY
A vector database stores and searches numerical representations of text.
Chunking converts large documents into manageable retrieval units.
Embeddings represent the semantic content of chunks.
Similarity search retrieves chunks related to a question.
Metadata provides source and structural information.
Good chunking preserves meaning and improves retrieval.
The retrieved chunks can then be supplied to a Transformer for grounded question answering.
