TITLE: Information Extraction
PURPOSE: Retrieval-friendly knowledge for a generative question-answering system.

SECTION: Core concepts
Information extraction identifies structured information from unstructured or semi-structured text.
Named entity recognition identifies spans that refer to entities such as people, organizations, and locations.
Entity linking connects a textual mention to an entry in a knowledge base when possible.
Relation extraction identifies relationships between entities.
Event extraction identifies events and their participants, attributes, and triggers.
Attribute extraction identifies properties associated with entities.
Keyphrase extraction identifies important phrases representing a document's content.
Temporal information extraction identifies dates, times, durations, and temporal relations.
Coreference resolution determines when different mentions refer to the same entity.
Information extraction can convert text into structured records suitable for downstream systems.

SECTION: Named entity recognition
Named entity recognition is commonly abbreviated as NER.
Typical NER labels include PERSON, ORGANIZATION, LOCATION, DATE, and MONEY.
Entity label sets vary by domain and application.
BIO tagging represents the beginning, inside, and outside of entity spans.
BIOES tagging adds explicit labels for single-token and ending positions.
Span-based NER predicts entity boundaries and labels directly.
Dictionary-based NER uses lists of known names or terms.
Rule-based NER can use patterns such as capitalization or regular expressions.
Neural NER models can learn contextual representations of entity mentions.
Domain-specific NER may recognize concepts such as diseases, chemicals, products, or legal entities.

SECTION: Relation extraction
Relation extraction identifies semantic relationships between entities in text.
A relation can be represented as a subject, predicate, and object.
Binary relations connect two entities.
N-ary relations can involve more than two participants or arguments.
Relation labels depend on the application and ontology.
Dependency parses can provide syntactic evidence for relations.
Transformer models can classify candidate entity pairs using contextual representations.
Relation extraction can be sentence-level or document-level.
Cross-sentence relations require linking information across multiple sentences.
Relation extraction errors can arise from incorrect entity boundaries or ambiguous context.

SECTION: Event extraction
Event extraction identifies event mentions and their semantic arguments.
An event trigger is a word or phrase that signals an event.
Event arguments are entities or values that participate in the event.
Event roles describe how arguments participate in an event.
Temporal arguments can specify when an event occurred.
Location arguments can specify where an event occurred.
Event coreference determines whether event mentions refer to the same event.
Event schemas define the event types and expected roles for a domain.
Event extraction is useful for building timelines and structured reports.
Implicit events can be harder to extract because they may lack an explicit trigger.

SECTION: Coreference and entity linking
Coreference resolution links mentions that refer to the same underlying entity.
Anaphora occurs when an expression refers back to an earlier mention.
Cataphora occurs when a reference points forward to information introduced later.
Pronouns often require discourse context for correct resolution.
Entity linking maps mentions to canonical identifiers.
Candidate generation produces possible entities for a mention.
Entity disambiguation selects the candidate best supported by context.
Knowledge-base descriptions can provide context for entity linking.
Alias and spelling variation can complicate entity linking.
Entity linking can improve consistency across extracted records.

SECTION: Temporal extraction
Temporal expression recognition identifies phrases referring to time.
Dates can be absolute such as a specific calendar date.
Relative expressions such as yesterday depend on a reference time.
Durations describe how long an event or state lasts.
Temporal normalization maps expressions to standardized representations.
Temporal relation extraction identifies before, after, overlap, or related relations.
Document creation time can help interpret relative temporal expressions.
Time zones can matter when extracting timestamps from global data.
Ambiguous dates require locale or contextual information.
Temporal extraction can support event timelines and scheduling applications.

SECTION: Methods and models
Rule-based extraction uses handcrafted patterns and domain knowledge.
Regular expressions are useful for structured patterns such as identifiers and simple dates.
Dictionaries can provide candidate terms for extraction.
Supervised extraction learns from annotated examples.
Sequence labeling models predict labels for tokens or spans.
Span classification models predict candidate spans and their types.
Dependency parsing can provide syntactic features for rule-based extraction.
Transformer encoders provide contextual representations for many extraction tasks.
Large language models can perform extraction through prompting or structured generation.
Hybrid systems combine rules, statistical models, and generative models.

SECTION: Evaluation and errors
Precision measures how many extracted items are correct among the extracted items.
Recall measures how many relevant items were successfully extracted.
F1 combines precision and recall.
Entity-level evaluation can require exact span and type agreement.
Partial-match evaluation gives different treatment to overlapping but non-identical spans.
Relation evaluation should consider entity identity and relation label correctness.
Error analysis can separate boundary, type, linking, and context errors.
Class imbalance can affect extraction metrics.
Annotation disagreement can indicate that an extraction label is ambiguous.
Evaluation should reflect the ontology and error costs of the target application.

SECTION: Applications and limitations
Information extraction can populate knowledge graphs from text.
Business intelligence systems can extract entities and relationships from reports.
Search systems can use extracted entities and metadata to improve retrieval.
Document processing can extract fields from invoices, forms, and reports.
Scientific text mining can extract experimental entities and relationships.
Customer-support systems can extract issue types, products, and requested actions.
Legal text mining can extract parties, dates, obligations, and cited references.
Extraction quality can degrade when the domain differs from training data.
Private or sensitive documents require appropriate access controls.
Human validation can be necessary when extracted records drive consequential decisions.
