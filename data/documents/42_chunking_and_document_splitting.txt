TITLE: Chunking and Document Splitting
PURPOSE: Retrieval-friendly knowledge for a generative NLP question-answering system.
USAGE: Atomic statements support semantic retrieval, grounded answer generation, and focused knowledge lookup.

SECTION: Foundations
Chunking splits a document into smaller units for storage, retrieval, or model processing.
A chunk is a segment of source text used as a retrieval unit or generation context.
Document splitting is useful when documents exceed context limits or precise retrieval is needed.
Chunk boundaries affect whether retrieved text contains enough evidence to answer a question.
Good chunks preserve coherent ideas while avoiding unrelated content.
Chunk metadata should preserve the connection to the original source.
Chunking strategy should match document structure and content type.
One strategy may not suit prose, tables, code, and transcripts equally well.
Chunk quality should be evaluated using realistic questions and retrieval results.
Chunking is a core design choice in many retrieval-augmented generation systems.

SECTION: Fixed-size chunks and overlap
Fixed-size chunking divides text into units with a configured character or token length.
Token-based chunking aligns chunk size more closely with model token budgets.
Character-based chunking is simple but can produce uneven token counts.
Fixed boundaries can split a sentence or concept across two chunks.
Large chunks may dilute relevance with unrelated material.
Small chunks may omit definitions, qualifications, or necessary context.
Overlap repeats some content from one chunk in the next.
Overlap can preserve context when an important statement crosses a boundary.
Excessive overlap increases index size and can return redundant passages.
Chunk size should be selected using query types, context budgets, and evaluation results.

SECTION: Structure-aware and semantic chunking
Structure-aware chunking uses document organization to determine boundaries.
Markdown headings provide natural semantic boundaries.
Nested sections can be represented with parent-heading metadata.
Lists should remain associated with the statement that introduces them.
Tables may need row-aware chunking to preserve headers and values.
Code documents can be split by functions, classes, or logical modules.
Semantic chunking uses meaning or topic changes to select boundaries.
Sentence embeddings can estimate semantic similarity between adjacent sentences.
A large semantic shift can indicate a potential chunk boundary.
Semantic chunking can cost more computation and depends on embedding quality.

SECTION: Special formats and metadata
Tables require preservation of column names, row values, and units.
FAQ documents can often be chunked as question-answer pairs.
Legal documents may require section numbers and clause headings to remain attached.
Scientific papers benefit from section-aware chunks and figure or table references.
Chat transcripts can be segmented by speaker turns or topic changes.
Slide decks may need title, slide number, and bullet hierarchy in metadata.
Scanned documents may require OCR before chunking.
Metadata can include source ID, title, heading, page number, and timestamp.
Stable chunk IDs support updates, deduplication, and citations.
Access-control metadata should be applied during retrieval, not only after generation.

SECTION: Evaluation and troubleshooting
Retrieval recall can measure whether chunks containing answer evidence are retrieved.
Retrieval precision measures how much of the retrieved set is useful.
Answer accuracy reveals whether chunks provide enough information for generation.
Chunk-size experiments should use a fixed representative evaluation set.
Overlap experiments should measure retrieval quality and index growth.
Redundancy rate can reveal when overlapping chunks return nearly identical passages.
Latency and storage costs should be included in chunking tradeoff analysis.
Unanswerable questions can test whether chunks cause unsupported responses.
A split definition may separate a term from its explanation.
A split table may detach values from column headings.
Small chunks may omit caveats or antecedents.
Large chunks may contain many irrelevant sentences.
Poor OCR can corrupt text before chunking begins.
Mitigations include structural parsing, overlap, parent context, deduplication, and retrieval evaluation.
Chunking failures should be diagnosed by inspecting actual retrieved passages and answer errors.
