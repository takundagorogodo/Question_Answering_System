TITLE: Question Answering
PURPOSE: Retrieval-friendly knowledge for a generative question-answering system.

SECTION: Core definitions
Question answering is an NLP task that produces an answer to a natural-language question.
A QA system receives a question and may use documents, structured data, or a model's learned knowledge.
Open-domain QA allows questions across many topics.
Closed-domain QA restricts questions to a specific subject or knowledge source.
Extractive QA selects an answer span from a supplied context.
Generative QA produces an answer using a language generation model.
Multiple-choice QA selects one option from a set of candidates.
Yes-no QA returns a binary answer when the task permits it.
Conversational QA uses dialogue history to interpret follow-up questions.
Knowledge-base QA maps questions to structured facts or queries.

SECTION: Retrieval-augmented generation
Retrieval-augmented generation combines information retrieval with generative language modeling.
A retriever selects documents or passages that may contain evidence for a question.
A generator uses retrieved context to formulate an answer.
RAG can reduce dependence on information stored only in model parameters.
Chunking divides documents into smaller retrieval units.
Embeddings represent text as vectors for semantic similarity search.
Vector search retrieves passages whose embeddings are similar to a query embedding.
Hybrid retrieval combines lexical and semantic retrieval signals.
Reranking reorders retrieved candidates using a more detailed relevance model.
Grounded generation asks the generator to answer using retrieved evidence.

SECTION: Question types
Factoid questions usually ask for a specific entity, value, date, or short fact.
Definition questions ask what a concept means.
Why questions ask for causes, reasons, or explanations.
How questions ask for procedures, mechanisms, or methods.
Comparison questions ask about similarities and differences between concepts.
List questions ask for multiple items that satisfy a condition.
Multi-hop questions require combining information from multiple pieces of evidence.
Analytical questions require reasoning over retrieved facts rather than copying one sentence.
Temporal questions depend on dates or time ranges.
Conversational questions may contain references such as it, they, or that concept.

SECTION: Knowledge-base preparation
Knowledge-center documents should use clear topic headings.
Atomic statements are easier to retrieve than long paragraphs containing many unrelated facts.
Consistent terminology improves retrieval and generation.
Definitions should state the concept before adding detailed explanation.
Examples should be labeled so a generator can distinguish them from general rules.
Limitations should be stored alongside methods to reduce overconfident answers.
Synonyms and alternate terminology can improve query matching.
Cross-references can connect related concepts across documents.
Stable identifiers or topic names can help organize a large knowledge base.
Duplicate or contradictory facts should be detected before indexing when possible.

SECTION: Retrieval and chunking
Chunk size affects how much context is available for answering a question.
Very small chunks may omit information needed to interpret a fact.
Very large chunks may reduce retrieval precision because they contain unrelated material.
Overlapping chunks can preserve context across chunk boundaries.
Chunking by headings can preserve semantic structure.
Chunking by sentences creates small atomic retrieval units.
Metadata can include topic, source, section, language, and document identifier.
Metadata filtering can restrict retrieval to the appropriate knowledge domain.
Top-k retrieval returns a specified number of candidate passages.
Reranking can improve the order of candidates before generation.

SECTION: Generation and grounding
A generator should distinguish retrieved evidence from instructions or unrelated text.
Grounded answers should avoid introducing unsupported claims when the evidence is insufficient.
Citation-aware generation can associate answer statements with retrieved sources.
Answer synthesis combines information from multiple retrieved passages.
Context ordering can influence which retrieved evidence the generator uses.
Prompt instructions can require concise answers, definitions, examples, or step-by-step explanations.
Generation temperature can influence output variability.
Lower randomness is often useful for factual QA tasks.
An abstention policy can allow a system to say that the available evidence is insufficient.
Answer length should match the complexity and requested format of the question.

SECTION: Evaluation
Exact match measures whether a predicted answer exactly matches a reference answer under a defined normalization.
Token-level F1 measures overlap between predicted and reference answer tokens.
Retrieval recall measures whether relevant evidence appears among retrieved candidates.
Retrieval precision measures how much of the retrieved set is relevant.
Answer faithfulness measures whether generated claims are supported by available evidence.
Answer relevance measures whether the response addresses the user's question.
Human evaluation can assess correctness, completeness, relevance, and clarity.
End-to-end QA evaluation should separate retrieval errors from generation errors when possible.
Adversarial evaluation tests robustness against misleading or irrelevant context.
Evaluation datasets should match the target domain and language.

SECTION: Failure modes
Hallucination occurs when a generated answer contains unsupported or fabricated information.
Retrieval failure occurs when relevant evidence is not retrieved.
Context contamination occurs when irrelevant or malicious text influences generation.
Ambiguous questions may have multiple valid interpretations.
Outdated knowledge can produce incorrect answers when the knowledge base is not refreshed.
Contradictory documents can cause inconsistent answers.
Entity confusion occurs when the system mixes facts about similarly named entities.
Over-compression can remove important qualifiers from retrieved evidence.
Answer copying can produce awkward or overly long responses.
Failure to abstain can turn uncertainty into an apparently confident incorrect answer.

SECTION: System design and security
Access control should restrict retrieval to documents the user is authorized to access.
Prompt injection can attempt to manipulate a model through retrieved or user-provided text.
Retrieved documents should not automatically be treated as trusted instructions.
Sensitive information should be protected according to the system's privacy requirements.
Logging can support debugging and quality monitoring but should avoid unnecessary sensitive data retention.
Rate limiting can protect QA services from excessive requests.
Caching can reduce repeated retrieval and generation costs.
Latency should be measured across query processing, retrieval, reranking, and generation.
Observability should record enough information to diagnose retrieval and generation failures.
Versioning knowledge sources helps reproduce answers and investigate changes.
